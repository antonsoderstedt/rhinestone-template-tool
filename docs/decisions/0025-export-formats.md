# ADR 0025: Export formats

**Status:** accepted · **Date:** 2026-11-22 · **Plan items:** D1, D2, D5

## Decision

- **SVG stays the cut file.** Every hole is a `<circle>`, in mm, never rasterised.
- **DXF and EPS** are added for cutters and programs that do not open SVG (`export/vectorExport.ts`). DXF is ASCII R12-style with
  `$INSUNITS` = mm and one `CIRCLE` per stone on layer `STONES`; EPS has a bounding box in points and one stroked arc per
  stone. Both flip y (they point up), order the stones the same way every time, and refuse a template that is not in mm.
- **PDF** is not generated by code. "Print true size" opens a page sized to the design with a 50 mm check square, and the
  browser's print dialog saves it as a PDF or prints it. It places the exported SVG; nothing is drawn through a canvas.
- **PNG is deliberately not offered.** AGENTS.md forbids routing the export through `<canvas>` or an image encoder, and a PNG
  of the template would only be a picture of it. A customer-approval picture can be had from "Print true size" as a PDF.
- **Copy SVG** puts the exported text on the clipboard.

## Consequences

Colour is never the stroke in any of these formats (see the stone colour note in the engine spec).
